Checklist

Common holes in AI-built apps

A short list for founders. These are holes I keep seeing in websites and apps built with AI tools. Each line is something you can check yourself. This is not a full test, and it is not a security booking.

Authorised security checks: bookings opening soon. Only check systems you own.

Exposed API keys in front-end code

How to check: search the front-end source, and the built files the browser downloads, for keys, tokens, and other secret-looking strings.

Missing auth checks on API routes

How to check: open an account or data route in a private window, while signed out, and again as a second user. You should not see someone else's data.

Database rules left open

How to check: open the database settings and confirm row rules are on (Supabase RLS off means they are open), then try to read a table with the public key while signed out.

No rate limiting on login or sign-up

How to check: submit the same login, and the same sign-up, many times in a row. The app should slow or stop you, instead of accepting every try.

Password reset flaws

How to check: request a reset, open the link, and see whether it expires, whether it still works after you use it once, and whether you can finish it on your phone.

Broken mobile sign-up

How to check: create an account on a phone-width screen, including when the keyboard covers the button, and complete any email confirmation step.

Missing error states

How to check: turn the network off, submit a form, and enter a value the app should reject. Each one should say what went wrong, in words.

Accessibility basics

How to check: run automated checks against WCAG 2.2 AA plus a manual pass on the sign-up page, with the keyboard only, a visible focus, labels on fields, and text you can read.

Payment and billing edge cases

How to check: start checkout, go back, refresh, and use a declined test card if your provider gives you one. The plan on screen should match the plan you picked.

Sensitive data in URLs and logs

How to check: after sign-up and after a password reset, look at the address bar and the browser network log for emails, tokens, or reset codes.
